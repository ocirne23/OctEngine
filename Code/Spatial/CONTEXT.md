# Spatial
Library documentation for `Code/Spatial`. Read `.claude/CLAUDE.md` first (rules, building, style, dependency direction).

* High-performance spatial index for culling and position lookup, independent of the entity hierarchy. Implicit 64-ary hierarchy over per-level hashed grids — 11 levels, cell size ×4 per level (finest = compile-time `SPATIAL_FINEST_CELL_SIZE`, default 2 m → ±2097 km), BMI2 Morton keys (`Spatial:Morton`), each `CellRecord` holds a 64-bit child-occupancy mask so queries descend with bit scans. API takes dvec3 (quantized to an int64 lattice); per-entry data is SoA with cell-relative float positions; query math is reference-relative float — exact at planet scale
* `Globals::spatialIndex`: `initialize()` before world spawns; `registerEntry(pos, radius, userData, layerMask)` → `SpatialHandle`/`SpatialEntry` RAII; `updateEntry` per frame (same-cell rewrite ~4 stores; cell changes staged into PerWorker lists — callable from any job, one visitor per entry; register/unregister/commit/setLayerMask are main-thread); `commitFrame()` once per frame drains + sweeps. Queries read-only between commits: `querySphere/queryAABB/queryFrustum/queryRay/queryNearest`. Two visibility stamp sets (`markVisibleSet(Main, frustum)` + `markVisibleSphere(Near, ball)`; `getPassMask`/`isVisible`) — both MULTITHREADED (`traverseParallel` in Query.cpp: the top level is a handful of huge cells, so a serial frontier expansion first splits the tree into ≥ workers×4 subtree roots — classifying cells and emitting the upper cells' own few entries as it goes — then a grain-1 High `parallelFor` runs `traverseCell` per root, "Spatial mark visible" spans on the worker tracks. Thread-safe by structure: an entry lives in exactly ONE cell so no two roots stamp the same slot, cell maps only mutate in commitFrame, and per-traversal counters (`TraverseStats`) accumulate locally and merge once — which also fixed the pre-existing stats race from concurrent script-worker queries; `OcclusionBuffer::isVisible`'s hidden-cell counter went atomic with a plain-int mirror for its tweak, since the tweak panel binds a raw `int*`); the App drives all of it through ONE call, `SpatialIndex::update(camera, frustum, viewProjRelCamera)` (commit + cull-dist + mode/freeze gate + margin-inflated Main stamp with occlusion + Near ball with requery hysteresis) — AS A JOB in every mode: `kickUpdateJob(Renderer::getCullView(camera, viewportRect))` / `joinUpdateJob()` (the `CullView` — a Core.Frustum type, since Spatial and RendererVK do not link each other — is copied into members, one "Spatial cull" High job; main.cpp kicks right BEFORE `physics.update`, overlapping `audio.update` + the renderer's "Begin frame job" — see RendererVK — and joins before `world.update`; an INVALID view skips that frame's whole update, spawn guards covering the stale stamps). The window is the frame's only index-QUIESCENT stretch: the entity-change drains / net receive / game.update are the last pre-pass writers, contact scripts fire only AFTER the join (`physics.dispatchContactEvents`), and the entity-change drains / net receive / game.update above it are the last registers (commit relinks cells and register's pool growth reallocates the SoA the traversals read — neither may overlap a query). NOTHING added between the kick and the join may touch the index. The frustum comes from `Renderer::computeCullFrustum(camera, viewportRect)` BEFORE beginFrame (camera + viewport are final by then; TAA jitter is never baked into the mvp; it applies the viewport rect and publishes getCenterViewProj early) — bit-identical to the UBO's by construction: both go through `computeCenterViewProj`, the ONE place the center view-projection is built. VR kicks the SAME job on LAST frame's head view (`getCullView` returns the camera+frustum stored at the end of each VR beginFrame — one frame of cull latency, absorbed by the culling margin + near-ball slack; the fresh pose only exists after `xrWaitFrame` inside beginFrame, so the job overlaps that stall; the first VR frame's view is invalid = cull skipped; `computeCullFrustum` still asserts !VR)
* Entity integration: EVERY entity registers at the end of `Entity::create` (`Entity::spatialEntry`): layer `SpatialLayer_Entity` always, plus `SpatialLayer_Render` when it has a render node (bounds from `RenderNode::getWorldBounds`, skinned × "Skinned radius scale"; else a point at the entity position). Gameplay queries stay on the Render layer; the Entity layer is the World's update-selection layer. Update pushes per-pass masks — Main-visible entities push `PASS_ALL`, Near-only push `PASS_SHADOW|PASS_GI` so shadows/GI keep off-screen entities. UPDATE TIER PASSES (`ESpatialPass::UpdateTier0/1/2`, bits `SpatialPassBit_UpdateTier*`/`SpatialPassBits_UpdateTiers`): the World's SIM LOD, not rendering — `setUpdateLod(focus, count, radii)` (≤ `MaxUpdateLodFocus` 16 points) makes `update()` stamp the three passes with `markVisibleSpheres` (ONE stamp generation over the union of the balls — `markVisibleSphere` per call would leave only the last ball) BEFORE the culling-mode/freeze gate, so selection never stops with culling; `visiblePerPass` counts overlapping balls twice. `isStampedCurrent`/`stampCurrent` are MAIN-THREAD single-entry stamp accessors (exact compare, no spawn guard) the World uses to mark the ancestors of a selected entity between the join and the pass. See the SIM LOD bullet in `Code/Entity/CONTEXT.md`. `Spatial/Culling/Mode`: Off / Stats only / Cull (default) / Main only (debug — visibly kills off-screen shadows/GI); `Freeze` stops re-stamping to inspect the culled set
* CPU software occlusion (`Spatial:Occlusion`, `Globals::occlusionBuffer`, Spatial/Occlusion tweaks, default off): the largest triangles of static mesh colliders (from CollisionCache occluder sets, registered by PhysicsComponent, RAII `SpatialOccluder`) rasterize camera-relative into a 256x144 CPU depth buffer + 8x8 max-depth blocks; plugged into the Main stamp as `IOcclusionTester` — occluded cells drop from the MAIN pass only. Conservative toward visible
* Static tier: entries unchanged for N frames (Spatial/Static tweaks) promote into per-level Morton-sorted SoA ranges (`StaticStore`), budgeted one level per commit; any change demotes. Sphere/AABB/frustum testers all test static ranges 8-wide (AVX2 `test8`)
* Stress harness (`Globals::spatialStress`, Spatial/Stress tweaks): synthetic entries on `SpatialLayer_Stress`, churn, timed queries, brute-force verify; stats under Spatial/Stats
* Scripts: `ctx->spatialQueryRadius` / `ctx->spatialGetNearestEntity`; NodeEditor "Get Nearest Entity" + "For Each Entity In Radius"
* Planned (not yet built): Threading-parallel QUERIES — the markVisible* stamps already fan out (see above); the query* entry points still traverse serially (their emit appends to one out-vector, so they need per-task collection before they can ride `traverseParallel`)
