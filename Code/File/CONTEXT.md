# File
Library documentation for `Code/File`. Read `.claude/CLAUDE.md` first (rules, building, style, dependency direction; the asset text formats are listed there under "Asset files").

* Asset + filesystem functionality. `ISceneData::createAssimpLoader()` for model files, `createProceduralLoader()` for generated geometry (terrain, skysphere, debug shapes)
* Cooked scene cache: `ISceneData::loadCached(path, mergeNodes, preTransform, SceneCookOptions)` (World uses it for every non-procedural container) serves a binary snapshot (`Assets/Local/Cooked/<stem>_<hash>.vsc`; `File:CookedSceneData` reader, SceneCooker.cpp writer) validated by magic/version, source mtime+size, options hash, per-converted-texture stamps — any mismatch re-imports and re-cooks in place. Cooking bakes meshopt LOD chains (so changing LOD tweaks recooks on next start) and converts non-DDS textures (loose AND embedded) to BC1/BC3(alpha)/BC5(normals) .dds so they mip-stream (alpha-masked diffuse mips alpha-coverage-rescaled). Skinned/animated scenes always bypass the cache. Delete `Assets/Local/Cooked/` to force a recook
* `AssetParser` (`File:AssetParser`): the text format behind all engine text assets — indentation-defined hierarchy of `AssetNode` (key + values + children), `#`/`//` comments, quoted strings, comma vectors; `loadAssetFile`/`parseAssetText`/`writeAssetText`, case-insensitive `find`, typed accessors. `File:ObjectDescription` parses .oc into `ObjectContainerDesc` (`loadObjectContainerDesc`) — lives here so Procedural's scatter assets import through .oc too
* `FileSystem` (`File:FileSystem`) is THE disk seam — the ONLY code that includes `<filesystem>`/`<fstream>` (Core stopped exporting them). Plain UTF-8 `std::string` paths, no `std::filesystem::path` in any consumer. API: reads/writes (`readFileStr`/`readFileBytes`/`writeFileStr`/`writeFileBytes`), queries+mutations (`exists`/`isDirectory`/`isRegularFile`/`fileSize`/`lastWriteTimeSec`/`copyLastWriteTime`/`createDirectories`/`remove`/`removeAll`/`rename`/`copyFile`/`listDirectory`(+`Recursive`, returns `DirEntry{path,name,extension,isDirectory,size}`)/`currentPath`/`setCurrentPath`/`absolutePath`/`canonicalPath`/`weaklyCanonicalPath`/`relativePath`) and pure PATH MATH that touches no disk and carries no thread rule (`join`/`parentPath`/`filename`/`stem`/`extension`/`replaceExtension`/`normalize`/`isAbsolute`/`pathEquals`)
* MAIN-THREAD IO ASSERT: every FileSystem IO call asserts when it runs on the main thread (the thread that called `initialize()`) — disk latency there is a frame hitch. Intentional main-thread IO says so, either with the RAII `FileSystem::AllowMainThreadIO` scope (thread_local, nestable; do NOT hold one across a fiber wait — /GT) or the trailing `allowMainThread` flag per call. Every FileSystem IO function also carries a profile marker named after it ("FileSystem::readFileStr", ...) in the File category — via a local `IoScope`, NOT a plain ProfileScope: IO runs on threads the profiler deliberately leaves unregistered (the transient startup texture-bake pool), where ProfileScope would dereference a null track, so the marker no-ops when `threadTrack()` is null. `FileSystem::assertIoThread(allow)` is the same main-thread check, exposed so File's OWN internals (CookedSceneData/SceneCooker stream binary ranges through `FILE*`/ifstream, which no read-it-all API can express) declare their policy too. Already marked as main-thread-by-design: main()'s whole INIT phase (one scope, released at `initScope.stop()` — so anything the FRAME LOOP does trips the assert), `loadAssetFile` (prefab/.oc text, read once per asset at first spawn then cached), scene load/cook, shader compiles, ScriptHost compile/load, the editor panels (explicit user actions), game save/load
* `FileSystem::initialize()` sets the working directory to `Assets/` and records the main thread
