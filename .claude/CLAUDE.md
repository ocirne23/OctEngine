## Style
* Exclusively C++20 modules (.ixx), no headers
	* Most libraries use module partitions: `export module RendererVK:Renderer;` in the interface .ixx, `module RendererVK;` in the implementation .cpp; public surface re-exported from `Public/<Lib>.ixx`
	* `Core` uses dotted module names (`Core.Tweaks`, one module per .ixx); UI uses partitions (`UI:Scene`, `UI:ProfilerPanel`) except `UI.Gizmo`/`UI.fwd`
	* `Public/` .ixx's are importable from outside the library; `Private/` is internal
	* `Core` re-exports std headers as header units — if a std header is missing, add it to `Code/Core/Public/Core.ixx`
	* `Core.fwd` / `*.fwd.ixx` hold forward declarations
	* One exception: `Script/Public/ScriptAPI.h` is a plain header — the ABI shared with runtime-compiled script DLLs, `#include`d on both sides
* No new/delete, only memory-safe types; raw pointers are non-owning
* Minimal comments — only where intent is genuinely hard to communicate
* Prioritize performance
* Engine singletons live in `export namespace Globals` inside the owning .ixx (`Globals::rendererVK`, `device`, `input`, `ui`, `world`, `physics`, `scriptHost`, `scriptEvents`, `assetRegistry`, `time`, `allocator`, ...). Cross-library teardown is ordered ENTIRELY by init_seg — `Code/Core/Private/InitSeg.h` (in every TU via forceinclude.h) is the single authority: `OC_SEG_*` section defines + the `OC_INIT_SEG(seg)` macro (`__pragma`, since `#pragma` doesn't macro-expand). Destruction = reverse construction; teardown order `ui → world → scriptEvents → networkManager → jobSystem → renderer globals → plain ".CRT$XCU" (audio, physics, spatialIndex, entityAllocator, input, ...)`. Every EntityPtr holder destructs before ~JobSystem (which runs shutdown(): entity destruction reaches PerWorker::local(), needing the main thread's live worker context), NetworkComponents unregister before ~NetworkManager closes the host, and world's caches release into the still-live renderer/audio. main() has NO explicit teardown calls — a new global that holds EntityPtrs or whose dtor calls another library's global must slot into InitSeg.h. Globals in *different* libraries otherwise have no defined construction order (see `ScriptEventManager::initialize` for the register-from-main pattern)
* int8/uint64-style typedefs from `Core`; glm via `Core.glm`; `assert` compiled out in non-debug via forceinclude.h

## RendererVK
* Modern Vulkan renderer (minimum spec RTX 2000); Device Generated Commands for everything; reversed-Z main view (near=1/far=0; shadow maps stay standard; fullscreen passes disable depth test)
* Lights culled via a world-space hash table into distance-scaled grids; GI via scrolling clipmap radiance cascades (ray-traced probes); RTAO, TAA, PCSS cascades, volumetric fog, GPU compute skinning. An "RT sun shadow" toggle replaces the PCSS cascades entirely (shadow cull+draw skipped)
* Long-range sun shadows ("Shadows/Terrain march *"): past the PCSS `Max distance` and `RT/TLAS Range`, distant pixels cone-march the baked terrain height cascades (`terrainSunVisibility` in `terrain_height.inc.glsl`) and take `min` with the shadow term; the march fades in inside cascade range so the handover is seamless. Steps double from `Terrain march bias` (also the self-shadow bias). Deterministic — no jitter or temporal integration
* Everything upstream of composite is linear HDR: `EyeAdaptationPipeline` (log-luminance histogram auto-exposure) feeds `CompositePipeline` (HDR→display into the swapchain before ImGui; tonemap off/Reinhard/ACES/AgX)
* Frame order (`recordCommandBuffers()`, called from `present()`): skinning → ocean sim → indirect cull → light grid → force compute → particle sim → shadow cull+draw (unless RT sun shadow) → G-buffer → GI probes → RTAO → volumetric fog → scene forward → TAA → eye adaptation → composite + ImGui. Inside scene color: static mesh forward → decals → GI-probe debug → debug lines → force field → particles → fog apply
* Layout under `Private/`:
	* `Objects/` — thin Vulkan wrappers (Device, SwapChain, Buffer, ComputePipeline/GraphicsPipeline, AccelerationStructure, GBuffer, SceneColor, ShadowMap, GpuProfiler, BakedWorldMap, ...)
	* `Pipeline/` — one class per pass/feature (StaticMeshGraphics, GBuffer, GIProbe, RTAO, TAA, VolumetricFog, EyeAdaptation, Composite, Skinning, DebugLine, Particle, Decal, ForceField, OceanSimulation, light grid + indirect/shadow cull compute, shadows). Each registers its own tweaks
	* `Data/` — MeshDataManager, TextureManager, TextureStreamer, MeshStreamer, StagingManager, ShaderDatabase, GpuCrashTracker (Aftermath)
	* `Renderer.ixx/.cpp` — orchestrates everything; per-pass `record*()` methods
	* `OpenXRSession.ixx` — VR (`Globals::openXR`, implements `IVrSession`). Two-phase init around Vulkan device creation; stereo = 2-layer multiview swapchain; in VR the editor viewport sub-rect is ignored. `Renderer::beginFrame(camera, viewportRect)` applies the rect (`setViewportRect` is private — rect changes only at frame boundaries; beginFrame builds the projection from its aspect)
* Scene objects: `ObjectContainer` wraps one loaded `ISceneData`; `spawnNodeForIdx()` returns a `RenderNode` (RAII, move-only), `spawnSkinnedNode()` the GPU-skinned variant (AnimatorComponent feeds the bone palette via `allocateSkinningPalette`/`setSkinningPalette`). Destroying a RenderNode recycles without GPU sync (transform slots free-listed, skinned bundles parked in place per container, rebased sub-node offsets shared). `~ObjectContainer` frees ALL renderer resources (`Renderer::removeObjectContainer`)
* Per-frame instance flow: `renderNode(node, passMask)` is LOCK-FREE (callable from any job between beginFrame/present; atomic cursor claims, monotonic — on overflow the tail drops one frame, `m_instanceOverflowStart` CAS-min records it, present() clamps, capacity regrows next beginFrame; NEVER roll a bump cursor back). `addLightInfo`/`addFogVolume`/`addDecal` are lock-free too; `addDebugLine` + transform dirty lists are `PerWorker`-staged, merged in present(). Pass masks `PASS_MAIN/SHADOW/GI` (Layout.ixx = Spatial's bits); main cull, shadow cull, and GI TLAS writer each early-out on their bit (TLAS also range-bounds by `RT/TLAS Range`). Transforms upload SPARSELY: write only via `RenderNode::setTransform` (change-detected, per-frame-in-flight dirty lists) — a mutable getTransform would bypass tracking
* Texture mip streaming (`TextureStreamer`, "Texture Streaming" tweaks): DDS textures load tail-only (mips ≤128px) and stream against a VRAM budget by camera priority. Residency changes recreate the image and rewrite the slot in all 7 bindless texture arrays (UPDATE_AFTER_BIND, applied per frame slot after the fence wait); disk reads on a worker thread; old images retire after NUM_FRAMES_IN_FLIGHT. Non-DDS/procedural/embedded textures are pinned at full res
* Mesh data streaming (`MeshStreamer`, "Mesh Streaming" tweaks): cooked scenes register mesh sets (source mesh + LOD levels + .vsc byte ranges); vertex/index mega-buffers are BitRangeAllocator free lists (`MeshDataManager`). Over "Mesh budget (MB)", least-recently-referenced sets unseen for "Mesh cold frames" evict: MeshInfos get indexCount 0 (DGC/shadow/TLAS become no-ops, no re-record; static BLASes persist as geometry snapshots), ranges free after NUM_FRAMES_IN_FLIGHT. Re-reference re-streams from the .vsc on a worker; the LOD selector renders the nearest resident level meanwhile. A LOD chain shares ONE BLAS at "RT/BLAS LOD level" (alias table; aliased RT meshIdx rides the TLAS instance sbtOffset for hit-shader fetches, materials stay per-instance); static BLASes copy-compact after build ("RT/BLAS compaction", ~30-50% back). Only cooked static meshes stream. With Spatial culling everything visible stays referenced, so only despawned containers and Col_ proxies go cold
* Mesh LODs ("LOD" tweaks): `LodN_<name>` meshes/nodes form authored chains (level>0 never instanced, like `Col_`); static meshes without authored LODs get meshopt-generated index-only chains (pre-baked by the scene cache). Selection is per-instance ON THE GPU (`mesh_lod.inc.glsl` in main + shadow cull; params live via UBO): instances push LOD0 and the cull redirects the draw — CPU sizes every chain member's bucket to the chain's full count, hysteresis lives in per-instance GPU slots (benign races), shadow cull selects stateless 4x/+2 coarser, GI needs no selection (one chain BLAS). Selection metric is screen-space error (meshopt simplify errors projected to pixels vs "Max error (px)"); authored chains without error data use projected diameter vs "Full-res pixels (Authored Lods)". renderNode keeps every level of a referenced chain warm; the cull falls back to the nearest resident level during re-streams. Skinned meshes get bind-pose-generated chains too (per-instance MeshLodGroups, recycled with the bundle); skinned output MeshInfos are excluded from static BLAS builds/compaction
* Record command buffers once (not per frame) when possible; call `setHaveToRecordCommandBuffers()` after invalidating changes
* Shaders are GLSL in `Assets/Shaders/`, compiled at runtime with glslang — shader edits need no rebuild; F5 calls `reloadShaders()`. `*.inc.glsl` are includes; `shared.inc.glsl`/`ubo.inc.glsl` structs must stay in sync with `Private/Layout.ixx` (`RendererVKLayout`). SPIR-V + source dumps land in `Assets/Local/` for Aftermath crash analysis

## Entity
* The ECS. An `Entity` (pos/scale/rot, parent, displayName, spawn template, refcount, `typeBits`, `flags`) and its components live in ONE allocation. `typeBits` masks the 10 component types (fixed order: Scene, Render, Animator, Physics, Audio, Particle, Force, Light, Network, Script — Script last; `EComponentID` in `EntityP.ixx`, `MaxInlineComponentTypes` 10); `getComponent<T>`/`hasComponent<T>` compute byte offsets from compile-time sizes (`Component.ixx`). Each component is a partition under `Private/Components/` (struct + `get*SpawnInfo`/`write*SpawnInfo` in .ixx, bodies in same-named .cpp); `Component.ixx` re-exports them and holds the shared machinery. Per-component .ixx's must NOT import `:Component` (cycle) — cross-component code goes in the .cpp implementation units. Adding a component type: new .ixx/.cpp pair with a `getId()` struct, `export import` from Component.ixx, entries in `EComponentID`/`inlineSizes`/`componentTypeName`, create/destroy switches in Entity.cpp, parse branch in `World::buildTemplate`, write branch in Prefab.cpp, require-slot fill branch in `ScriptComponent::syncScriptData` (a missing branch shifts every later slot — this crashed once), Entity.natvis offset entry, bump `MaxInlineComponentTypes`, and an Entity Editor section if authorable
* `EntityPtr`: intrusive refcounted handle (atomic). `Entity::create(template, transform)` placement-news into `Globals::entityAllocator` (lock-free: atomic chunk bump + tagged per-size-class Treiber free lists; blocks ≤64KB). Tree via `SceneComponent::children` + `Entity::parent`; `reparentEntity` moves ownership
* Tree spawns are ONE allocator block (template's cached `treeAllocSize`, bump-carved). While intact (`EEntityFlag_RootAllocation`/`ContiguousAllocation`) the root frees the whole block (refcount pre-walk `contiguousTreeSolelyOwned`); reparenting/deleting a member out of its birth tree SPLITS the allocation (`breakContiguousAllocation`: path ancestors demote to per-entity freeing, off-path subtrees promote to their own RootAllocations). Moving within the same allocation or grafting a whole allocation root never breaks anything
* `Entity::update` is a thin serial recursive wrapper around `Entity::updateSelf`, the ONE hot per-entity visit: Script → Network → Animator → Physics, compose world transform, refresh the SpatialIndex entry, push the RenderNode (gated on `spatialIndex.getPassMask` when Spatial culling mode ≥ Cull)
* Entity state lives in `flags` (`EEntityFlags`): `EEntityFlag_Enabled` (off prunes the subtree from update and suspends physics bodies; serialized as entity-level `Enabled false`, default true), `EEntityFlag_Frozen` (script Update/animator/physics don't tick, script events don't fire — what the Entity Editor sets on an open document). Frozen is a SUBTREE state written down the whole tree by `setFrozen`; `Entity::create` inherits it from the spawn parent, `reparentEntity` adopts the new parent's state — every check is a plain self `isFrozen()`, including entry points outside update (global script events, physics contacts). Script OnSpawn runs even frozen. `EEntityFlag_PhysicsSuspended` latches the disable walk (cleared up the new ancestor chain by `reparentEntity` — else a body joining a disabled subtree stays live and collides invisibly). Per-component `enabled` bools are independent of both
* PARALLEL entity update (`World::update(renderer, dt)`, always on): the tree is walked BREADTH-FIRST BY DEPTH, whole level concurrently (`parallelFor`). `updateSelf` emits children as `EntityUpdateNode{entity, parentWorld}` into `PerWorker` staging; the level barrier merges slots into the next level. The barrier IS the ordering guarantee — a parent always finishes before its children, so a child reads its parent only through `parentWorld` and all other writes land in the entity's own components. Thread-safe inline: scripts (DSL cross-entity access is parent→child writes / child→parent reads; world radius queries are the known open hole), animator + `setSkinningPalette` (disjoint regions), dynamic-body pose reads, `RenderNode::setTransform`/`renderNode`, `SpatialIndex::updateEntry`, audio follow, particle/force emitter slots. The pass NEVER writes to box3d. The gizmo entity uses the serial path
* `World` (`Globals::world`): `spawn("prefabName", transform)`, `spawnAssetFile("Entities/x.pre", ...)`, `createEmptyEntity`. Builds and caches `EntitySpawnTemplate`s (archetype + per-component `SpawnInfo` recipes); caches ObjectContainers, collision sources/meshes, retargeted clip sets — each source file imported once. `reloadPrefabs`/`invalidatePrefab` for editing (retired templates stay alive for live entities). OWNS the root entity list (`addRootEntity`/`removeRootEntity`/`rootEntities` const-only/`clearRootEntities`; roots die in ~World, ordered by the init_seg teardown scheme — see Style). Applies queued `EntityChange`s via `handleEntityChange(change, camera, viewportRect)`; UI notifications route back through `setOnPrefabOpened`/`setOnEntityRespawned` callbacks. `World::handleContactEvent` is the physics contact callback (passed to `physics.update` from main): invokes `PhysicsComponent::onContact` + the script's `OnPhysicsEvent`
* `AssetRegistry` (`Globals::assetRegistry`): `scanDirectory()` (cwd = Assets/) registers ObjectContainers (.oc), clips (.anm), animator graphs (.apl), prefabs (.pre) by name

### Multiplayer
* `Entity:NetworkManager` (`Globals::networkManager`) + `NetworkComponent` (ID 8). The inline component is identity only (netId + ownerClientId + `unique_ptr<NetEntityState>`, 16 bytes); all sync state lives in `NetEntityState` (NetworkComponent.ixx), allocated only inside a session. Role-exclusive state is a UNION of `ServerState`/`ClientState` (a process is one role for life; both trivially destructible); only `input`/`transferredOwnership`/`sleepDirty` are dual-role. Cross-role reads are bugs. The manager never null-checks `state`; the component's own update() and outside readers (EntityEditor, InputControls) must
* One App.exe for all roles: `--server [--port N] [--headless] [--tickrate N]` / `--connect <ip[:port]>` / `--no-encrypt` / no flags = single player (`ENetRole::None`, everything inert; `registerTweaks()` still runs). Hard cap `MaxClients` 32
* Thread contract: manager writes on the main thread pre/post the parallel pass (`receive()` before, `send()` after); `NetworkComponent::update` reads/writes only its own entity's block on workers. Client physics corrections go through the thread-safe body-command queue (`teleportBody`/`queueBodyCommand`) — never direct box3d writes from workers
* HEADLESS SERVER (`headlessServer` branching inside main() — one init sequence and ONE main loop for all modes): no window/renderer/UI/input. `World::setHeadless(true)` BEFORE any spawn makes `buildTemplate` emit only Scene/Physics/Script/Network components (component thunks do NOT null-check their handle — `//@@require`'s live `requirementsMet` gate is the guarantee a script never reaches an absent component, so a script using a stripped component simply never runs its entry points headless; cross-entity thunks still `getComponent`-check; `Renderer::isInitialized()` gates the few thunks that touch renderer state). Hull/Mesh colliders still build (container name parsed textually, renderer-free import). Loop: entity-change drains → receive → scriptContext → physics → world.update → send → Sleep-based tick limiter; Ctrl+C clean shutdown; 5s status line. Deliberately skipped headless: terrain/ocean/scatter + terrain collider (camera-centered streaming — the test scene carries its own ground), buoyancy, audio, spatial entries (only RenderComponents register, so radius queries see nothing server-side)
* SNAPSHOTS (server → clients, Unreliable ch0): server streams registered entities' LOCAL pos/rot at "Network/Snapshot Hz", chunked under "Snapshot max bytes", capped by "Max entities per tick"; per-record staleness dropped per entity by tick (chunk reordering harmless — deliberately not UnreliableSequenced). Change-detected against last-sent (epsilon tweaks) + a keyframe rotation (`serverTick % "Keyframe every ticks" == netId % ...`, default 20) so late/drifted clients converge. Rotation smallest-three quantized behind a live "Quantize" toggle carried in the header. Clients simulate locally and correct in `NetworkComponent::update` per the "Network/Correction" tweaks (targets published by `receive()` pre-pass, component reads only)
* OWNERSHIP: everything is server-owned by default; `netId` is minted only by the server, never authored (`Component Network` in .pre is pure presence, no children). `registerEntity` on the server creates/extends the root's spawn record (prefab, id base, transform), announced as a reliable Spawn and REPLAYED to late joiners — that replay is how the world arrives at connect. Clients adopt server ids in tree-DFS order; any other registration returns netId 0 = local-inert (never synced) — so client-only/server-only entities are just entities without a NetworkComponent, and id conflicts are structurally impossible. Static scenery that never moves should carry NO NetworkComponent. Unregistering the base id sends Despawn. Never store NetPeerIds on entities (they recycle); clients get a stable `clientId` at Hello/Welcome. `setOwner(root, clientId)` must run in the spawn's own frame (the record rides `m_dynamicRootIds`, purged at send()); later transfers use the per-entity OwnerChange message. `NetworkComponent::authority()` derives Local/ServerOwned/LocalOwner/RemoteOwner (worker-safe)
* CLAIMS (owner → server, Unreliable ch3): the owner simulates freely and streams input + claimed pose/velocities, PHASE-LOCKED to the physics step (`send()` fires them only on frames where `getStepCount()` changed; "Max update Hz" is only a thinning limit, counted in WHOLE STEPS (`stepCount - lastClaimStep >= round(stepHz / maxUpdateHz)`) and never against the wall clock — a step boundary falls partway through a frame while the net clock advances in whole frames, so a time comparison at the step rate measures just-under-interval and DROPS that step’s claim, which the passthrough extrapolates over and double-jumps: remote-client pulsing that vanished only when the limit was raised until it stopped binding; paused physics = no claims, correct). Each packet carries the last "Claim redundancy" claims (default 4, ring cap 8; redundancy beats reliable under loss); the packet record count comes from `validCount`, never seq, so a re-acquired entity can't replay a previous owner's poses. Quantized like snapshots with live ranges in the header. Claims follow the sleep policy (`sleepDirty`): every awake tick, one rest-pose claim on the sleep edge, then silence
* VALIDATION ("Network/Validation" tweaks): movement token bucket in metres refilled at "Max speed" per second of SERVER WALL CLOCK (never per-claim — packet rate is attacker-controlled), linear + angular velocity caps on EVERY accept path, trajectory raycast ("Path raycast" toggle), hard teleport cap; the first claim seeds the anchor but is still checked. "Max speed" (default 60) must exceed the fastest legitimate motion including free fall. Every float off the wire is finite-checked and quaternions re-normalized (NaN passes comparisons and poisons the solver). Accepted → the twin FOLLOWS the claim through the solver ("Twin follow gain", bounded `NudgeVelocity` = claimed velocity + corrective velocity toward the claimed pose; hard teleport only past "Twin resync (m)"). It is deliberately NOT teleport-pinned per claim: that collapsed the render interpolation (prev/curr both became the claim pose) and, since claims are sampled on the OWNER’s step clock while the server steps on its own, yanked the twin backwards whenever two server steps fell between two claims — pulsing visible on the SERVER’s own view. Other clients are unaffected either way because the passthrough sends them the owner’s stream, not the twin. `lastAcceptedClaimPos` anchors the next budget and re-emit to other clients via CLAIM PASSTHROUGH (the snapshot re-emits the newest accepted claim state instead of sampling the wobbling twin; extrapolates by claim velocity for a bounded gap; "Owner predict (ticks)" adds a constant forward shift at emit). Rejected → `violations`++ + `NetRecFlag_Forced` on snapshots for "Forced ticks"; the owner ignores corrections UNLESS Forced, an accepted claim clears Forced immediately, and `updatePlayerControl` yields input while Forced (steering against the correction is a tug-of-war)
* INTERACTION GRACE ("Interaction radius"/"linger"): server-owned bodies near OUR claim-driven bodies suspend corrections (they'd fight the push the player is applying; the twin gets the same push an RTT later). Proxy positions published in `receive()`, read from workers
* TRANSFER/STEAL/ARBITRATION ("Network/Ownership" tweaks, "Transfer enabled" kill switch): awake server-owned dynamics within "Transfer radius" of a client's PRIMARY hand over via per-entity reliable OwnerChange (server resets that entity's claim/validation state); revert after "Release delay" outside "Release radius". Primaries only as transfer sources (`transferredOwnership` distinguishes; client-side it means "owned but not the player" — `updatePlayerControl` skips it). Contact-driven STEALING (`stealOwnershipOnContact`, wired as the primary's `onContact` in main.cpp; needs `ContactEvents true`): last collider owns, never steals another client's primary. Primary-vs-primary contact ARBITRATES both for a window (twins go solver-owned, claims apply as bounded `NudgeVelocity`, records carry `NetRecFlag_Arbitrated`, input keeps steering); an object touched by two distinct clients within "Contest window" is CONTESTED → server-owned until the window decays. Late joiners get OwnerChange replays after the Spawn replay; a disconnect reverts transfers before tearing down primaries. `setOnClientJoined/Left` (main.cpp) spawns/tears down `Entities/Debug/netPlayerCapsule.pre` per client (upright `LockRotation` capsule, same movement/camera as the local player capsule)
* PHYSICS SYNC: a dynamic-body entity syncs the BODY (world pose + velocities, `NetRecFlag_Physics`; vels 3xu16 over live "Max vel"/"Max ang vel" ranges carried in the header). Server sends every awake tick, one sleep-edge record, then keyframes. DEFAULT client correction is the PHYSICAL PUSH: error × `Push pos/rot gain` becomes corrective velocity on top of the server's (capped; delivered as bounded impulses) so contacts and gameplay impulses COMPOSE — no teleport on this path, bodies still sleep inside the deadzones. Past the snap thresholds it enters CATCH-UP (boosted gains, still through the sim); hard `teleportBody` resync only at "Pos teleport threshold". EVERY teleport must also stomp `PhysicsComponent::prevPos/currPos/prevRot/currRot` AND claim the step (`physics->lastStep = getStepCount()`). NetworkComponent::update runs BEFORE PhysicsComponent::update on the same entity, so on any frame the sim stepped it would otherwise overwrite curr with `body.getPosition()` — which still holds LAST frame’s teleport, since teleports apply at the next physics.update — and render mix(thisFramePose, lastFramePose), i.e. BACKWARD, on stepping frames and correctly on the others. That alternation was the remote-entity pulsing. REMOTE-OWNED entities (other players) use BUFFERED SNAPSHOT INTERPOLATION instead ("Remote interp (ticks)", min/default 2 — must exceed 1 or playback degenerates to snapshot arrival; buy smoothness with snapshot RATE, not depth): `NetSnapshotRing` per entity (manager-owned, main-write/worker-read), playback at `newestTick − interpTicks` in server tick units, teleport-following with matched velocities + prev/curr stomps. Asleep records hard-sync once then queue `SetAwake 0`. Kinematic/static bodies use the entity-transform path
* EVENTS: `fireNetworkEvent(name[, data])` = local fire + Reliable ch1 (server relays to other clients). Payload ≤ `MaxEventDataBytes` 1024, static_asserted against the transport’s `netMaxSinglePacketMessage()` so a max-size event still rides in ONE packet; readable during dispatch via `currentEventData()`/`currentEventSender()` (script: `networkEventSender()`). Sender clientId is SERVER→CLIENT only (the server derives it from the receiving peer and re-serializes the relay — never trust a client-writable identity); a client-supplied sender netId resolves through `findOwnedEntity` (null unless that client owns it). `setEventFilter(clientId, name, data, senderEntity)` gates client-originated events (return false = dropped, not relayed); no filter = allow all — install one before any event grants state. Script event sends queue under a mutex, drained by `send()` (NetHost is main-thread-only)
* Session: 4-way transport handshake gates on `GameProtocolId` (bump on ANY wire change; NetFuzz's game mode mirrors it), then Hello→Welcome on Reliable ch2 marks the peer ready. Per-peer state MUST clear on Disconnected. Encryption is on by default at the NetworkManager layer (`s_encrypt = true` → `NetHostConfig::encrypt`, whose own default is false); it can't change on a live host, so `setEncryption()` before start, driven by `--no-encrypt`; both ends must match. Without it a peer is identified only by source address (trivially forged on a LAN)
* Testing: server key U throws `Entities/Debug/netPhysCube.pre`; client key C toggles player control (see Testbed keys); key K fires "NetPing". Demo `Entities/Debug/networkTest.pre` spawns at a FIXED transform (never camera-relative — both worlds must match). Link-sim tweaks (loss/latency/jitter) bind into `m_host.config()`; window title shows role + RTT/loss/KB/s
* PLAYER CONTROL (key C on a client, `InputControls::updatePlayerControl`): WASD/Space velocity-steers every locally-owned dynamic body camera-relative (`Network/Player` tweaks: Move speed/Accel/Jump speed — keep Move speed under Validation's "Max speed"); Space jump gated on a downward raycast; fly-camera movement released while active. The owning client simulates its body directly (main thread, before physics.update — direct setters sanctioned there), writes intent into `comp->input`, and the claim stream carries the resulting state

## Script
* Visual scripts compile to real DLLs: `ScriptHost` (`Globals::scriptHost`, Core-only) compiles a .scr with the installed MSVC toolchain (vswhere → vcvars64.bat, `cl /LD /std:c++20 /MD /Od /Zi /DSCRIPT_BUILD`, `/FI ScriptAPI.h`) into `Assets/Local/Scripts/`, caches by path, hot-reloads (`getOrLoad(path, forceRecompile)`) — F6 or a Script Editor save; live entities hot-swap. On failure the previous build is kept. A .scr is BODY-ONLY C++ (no `#include`/`#define`)
* COOKED alternative (`SCRIPTS_STATIC`, off by default): `Code/AppScripts` generates one aggregate TU that `#include`s every `.dsl` (only — .scr is not cooked) into its own namespace and compiles it INTO the engine (`/WHOLEARCHIVE:AppScripts` keeps the registrations). `REGISTER_*()` markers at the end of each .scr feed a static-init registry `getOrLoad` resolves from instead of cl/LoadLibrary — whole-program-optimized. All-or-nothing: one broken .scr fails the aggregate
* A .scr IS the generated C++ (entry points `OnSpawn`/`Update`/`OnDestroy`/`OnEvent`/`OnPhysicsEvent` + `ScriptEventCount`/`ScriptEventName`/`ScriptDataSize`) with the node graph appended as `//@graph`/`//@node` comments — the NodeEditor regenerates code from the graph; the file is also hand-editable
* .scr / the NodeEditor path is REMOVED from the running editor: no node panel, no `UI::m_scene`, no .scr open/create routes (the `NodeEditor/` sources remain in the tree for reference and still compile as unused partitions). A .scr shows as a plain text file in Content, isn't offered by script pickers, and isn't cooked; `ScriptHost` itself would still compile one if a .pre carried the path, but nothing authors that anymore. When Claude is asked for a script, author a .dsl via DslCompiler — never a .scr
* `ScriptAPI.h` is the host↔DLL ABI: C linkage, PODs/glm/raw pointers only. The `ScriptContext` function table is APPEND-ONLY (cached DLLs must keep working). Scripts see a layout-compatible `Entity` MIRROR (pos/scale/rot/parent only; offsets static_asserted in ScriptContext.cpp). Components a script can't name go through opaque handles: `ctx->entityGetForceComponent(entity)` returns `void*`, `ctx->forceGet*/forceSet*(handle, ...)` cast back host-side (the NodeEditor hoists the handle so lookup runs once)
* `ScriptModule`: DLL entry pointers + event names + data layout (`dataLayoutId`, `dataFields`, `requiredComponents`); don't cache function pointers across reloads
* DSL surface: `math.*` namespace (all scalar math, ANGLES IN DEGREES; `ocInverseLerp/ocRemap/ocMoveTowards/...` in ScriptAPI.h avoid double-evaluation; randomness is one ENGINE-side generator so hot-reload doesn't reset it). `self.animator.setFloat/setBool/setTrigger/...` — animation is the animator's surface, nothing names a clip. A getter-call member MUST register `writable=false` (a writable member's emit is used verbatim as an assignment target)
* ScriptData: `//@@data [private|public] <type> <name>` fields (default Hidden); exposed fields surface through `ScriptDataFields()` (`OcScriptField[]` — the only engine-side layout description). Properties panel edits them LIVE (never serialized); Entity Editor authors INITIAL values (text under `Component Script`/`Data` in .pre, re-applied by `applyInitialValues` after every `syncScriptData` reallocation)
* DSL containers: `T[]` arrays live ENGINE-side (`OcArray` generation-tagged handles; storage survives hot-reload). No unchecked reads: `foreach [ref] T x in c` iterates, `ifexist [ref] T x in c [at k]` is the single checked lookup. POD arrays resolve once to a span (`ctx->arraySpan`) — one ABI call per loop, elements are plain loads, `ref` binds a real C++ reference into the span; Entity/String arrays keep checked per-element reads. THE SPAN IS ONLY VALID WHILE THE ARRAY DOESN'T GROW — `checkContainerMutations` (ScriptLoader) enforces it as a whole-document fixed-point over the call graph (a push through a parameter poisons the function for every caller, conservative on purpose) and runs from BOTH `save()` and `load()` (the editor's Compile & Run path never parses); push/clear on a container an enclosing loop reads is refused. `ref` is refused on handle types and non-writable containers; non-`ref` elements can't be assigned. The editor-side grey-out (`ScriptLang::isContainerIterated`) is still syntactic — transitive mutation through a user function is authorable and gets refused at load
* `//@@require` is enforced LIVE by `requirementsMet` (mask test) at every entry point — not latched at spawn (hot-reload mutates the module in place). `OnSpawn` runs once, the first frame the entity qualifies (`onSpawnRan`); `OnDestroy` pairs with that flag, never the live check. `syncScriptData` re-allocates + refills require slots + clears `onSpawnRan` when the module layout changed; `syncScriptDataLive` (every post-spawn entry point) also re-registers the event listener (its stored pointer would dangle)
* FAULT CONTAINMENT (`OC_SCRIPT_FAULT_CONTAINMENT` at the top of ScriptComponent.cpp, default 1; 0 = raw calls, faults crash normally for clean dumps): every entry-point call goes through SEH-guarded invokers (`invokeScript*` in ScriptComponent.cpp — plain `__try`/`__except`, no C++ exceptions, zero cost until a fault): a hardware fault in script code (int divide by zero, stale pointer) marks the module `faulted` and logs instead of crashing. `requirementsMet` folds the flag in, so the script stops running everywhere (OnDestroy included — its data may be half-written); ScriptEventManager's direct OnEvent path checks it itself. A successful (re)load clears it (`loadDll`), so F6 / Compile & Run is the recovery. Deliberately unguarded: breakpoints, stack overflow, C++ exceptions (filter whitelist in `scriptFaultFilter`). Float div-by-zero never faults (FP exceptions stay masked — inf/NaN propagate)
* There is NO null in the DSL: absent values are OPTIONAL types (`Entity?`, readable only via `ifexist`); dead entities in arrays report a lookup miss
* The DSL subsystem (data model, autocomplete, bindings registry, save/load, C++ transpiler) lives under `Private/DSL/` as partitions re-exported from `Public/ScriptHost.ixx` — editor-agnostic; UI's Script Editor panel (`import Script;`) is its consumer. Types an outside importer needs must be `export`ed (partitions leak unexported types across same-module files — easy to miss)
* `DslCompiler <input> [output.dsl] [--compile]` (`Code/DslCompiler`, console exe) — THE way Claude authors .dsl files: write only the DSL text, the tool validates (same loader as the editor, full binding vocabulary), transpiles, and writes the exact file the editor's Save produces. USAGE + FULL LANGUAGE REFERENCE: `Code/DslCompiler/CONTEXT.md`. Raw input = single-`@` directives (`@require`/`@data`/`@event`) + TAB-indented code; the tool prefixes every line with `//@` (which is what turns `@require` into the stored `//@@require`) and wraps in the markers. An existing .dsl as input = normalize + regenerate C++ in place. `--compile` cl-compiles + loads the output through the real ScriptHost pipeline (the F6 path) — the final check that the script loads in the engine as-is. Errors print `<input>(<line>): <what>`; relative paths resolve against Assets/; exits via `_Exit` (nothing initialized, global dtors assume engine teardown order)

## Physics
* box3d (Erin Catto's 3D engine, C API) wrapped in `module Physics`; box3d linked PRIVATE, never leaks (ids stored as integer bits)
* `Globals::physics` (`PhysicsWorld`): `initialize()` once; `update(deltaSec, contactCb)` per frame (fixed-step accumulator; gravity/paused/interpolate/timescale/substeps/Hz under Physics/World tweaks). `createBody(PhysicsBodyDesc, span<PhysicsShape>)` (Box/Sphere/Capsule/Hull/Mesh; desc scale baked into shape dims), `castRayClosest()` (optional layer mask). * THREADING: `teleportBody(body, pos, rot)` is the ONLY way to move a body (mutex-queued, applied before the first step and before the paused check, handle revalidated via `b3Body_IsValid`). `PhysicsBody` deliberately has NO setTransform. The queue generalizes to a BODY-COMMAND queue (`queueBodyCommand(body, EBodyCommand, a, b, c)` + `queueSetGravity`): velocities, impulses, forces, torques, gravity scale, damping, setAwake, `NudgeVelocity` (bounded network correction), world gravity. EVERY script physics-write thunk queues (scripts tick on workers; even a velocity setter wakes the body into shared solver sets). All other box3d writes are MAIN THREAD ONLY; `PhysicsBody`'s direct setters remain as main-thread API. One frame of latency; reads return pre-write values. The DSL's `self.physics.teleport(position, eulerDeg)` rides the same queue and works on any body type
* Buoyancy: `setWaterSurface` + per-body probes ("Physics/Buoyancy" tweaks) — the App wires the ocean's `sampleWaterHeight` in
* `PhysicsBody`/`PhysicsJoint`/`PhysicsMesh`: RAII movable handles. Joints (`createDistance/Revolute/Spherical/WeldJoint`) take world-space anchors; `staticBody()` anchors to the world. `PhysicsMesh` (triangle BVH) must outlive Mesh shapes; Hull shapes clone. Mesh colliders only collide on static bodies
* `PhysicsComponent`: `Component Physics` in .pre (`Body` Static/Kinematic/Dynamic, `Shape` Box/Sphere/Capsule/Hull/Mesh, `HalfExtents`/`Radius`/`HalfHeight`/`Density`/`Friction`/`Restitution`/`MaxHullVertices`/`Sensor`/`ContactEvents`/`LockRotation` (solver-level lock on all angular axes — upright character capsules, see Entities/Debug/playerCapsule.pre; a locked dynamic body writes back only its POSITION, leaving entity.rot to scripts — player facing yaw); see Entities/Debug/physicsCube.pre). Hull/Mesh geometry comes from the sibling render mesh via `CollisionCache` (a World member — THE asset→physics bridge: snapshots a container's collision geometry from the same ISceneData one import serves, derives hulls/BVHs/occluder sets per container|node, caches each). `Col_*` meshes/nodes are collision proxies (replace the same-named render mesh for physics; never rendered)
* THE BODY OWNS THE POSE: created at spawn from the entity's world transform; physics never reads the entity's position again. Dynamic bodies write the simulated pose back each update (interpolated between fixed steps); non-dynamic bodies stay put. Gizmo-dragging or writing `self.pos` moves only the mesh — `teleportBody` is the only way to move a body. The static-mesh occluder is baked once at spawn (re-baked at the body's pose on resume-from-disabled). Sponza has a static mesh collider
* Contact/sensor events: shapes opt in via `ContactEvents`/`Sensor`; delivered per step through `update`'s contact callback (→ `World::handleContactEvent` → `PhysicsComponent::onContact` + the script's `OnPhysicsEvent` with the other entity, begin/sensor bools, contactId; sensor events have contactId 0). `getContactPoint(contactId, ...)` resolves world hit pos/normal, valid until the next update
* Layers: `PhysicsLayers::bit(name)` allocates one of 64 bits ("Default" = 0); shapes carry category/mask/group. In .pre: `Layer Debris` + `CollidesWith Default, Player` (or `All`/`None`) + optional `Group <int>`. Demo: physicsSphere.pre

## Force
* Forcefield bubbles: emitters (Team 0-7, Output, Reach, Focus, Distribution, Width + direction) project ANALYTIC fields with compact support spanning exactly `pos .. pos + dir*Reach`. Focus 0.5 = exact sphere spanning the line, 0/1 = exact cones; Width is a pure lateral scale; `distGain` bumps density along the line. TOTAL output is invariant across shape params (a quadrature-cached budget fold pre-applied to the uploaded Output — pinching densifies instead of shedding power); reach still scales the total. Gradients finite-differenced. Same-team fields SUM (metaballs); the drawn surface is the equal-field equilibrium `phi_best - max(iso, phi_second) = 0` — squish/pierce fall out of the math. Field math lives ONCE in `force_field.inc.glsl` (CPU lobe mirror in System.cpp drives the debug rings)
* `Globals::forceSystem`: `initialize()` from main (registers "Force" tweaks → `ForceFieldParams` pushed every update); `update(renderer, dt)` main-thread after world.update = the only writer of renderer force state. `createEmitter(...)` → RAII `ForceEmitter` (setters safe from the parallel pass — own slot only; `getAppliedForce()`/`getPressure()` = GPU readback ~2 frames latent); `createQuery(pos)` → `ForceQuery` (territory: `Result{owningTeam, inside, ownField, opposingField, valid}`, same latency)
* Renderer side (`RendererVK:ForceFieldPipeline`): emitter/query slots main-thread with free-list + retirement (readbacks slot-indexed so slots never re-pair with stale results). Rendering = one instanced draw of unit cubes (decal pattern, after debug lines / before particles) whose FS ray-marches the field through the emitter's reach box, bisection-refines, manual reversed-Z depth test; OWNERSHIP DISCARD dedups merged bubbles. Compute (`recordForceCompute`, after light grid): uniform 32 m emitter hash grid per frame (`force_grid.inc.glsl` + `force_grid.cs.glsl`; emitters over "Big reach threshold" bypass into a ≤64 global list); `force_emitter.cs` integrates opposing pressure (13-sample integral — a center-only tap reads zero when big bubbles press rims), `force_query.cs` evaluates points; host-visible readbacks. "Force/Use grid" off = brute-force A/B toggle
* `ForceComponent` (`Component Force` in .pre: `Team`/`Output`/`Reach`/`Focus`/`Distribution`/`Width`/`Centered` + local `Direction`/`Offset`; demo Entities/SphereField.pre) keeps its emitter on the entity's world transform (not frozen-gated — placement, not simulation). `Centered` (default true) pulls the emitter back Reach/2 so the bubble centres on the entity. Reach is world units, unscaled by the entity. No authored on/off — scripts use `setOutput(0)`. Script access via the `entityGetForceComponent`/`forceGet*`/`forceSet*` handle ABI; NodeEditor Get/Set Force nodes
* `ForceEmitter::getEquilibriumRadius()`: pressure-aware CURRENT bubble radius estimate — the closed-form iso profile at the widest station with the threshold raised to max(iso, pressure readback). An AVERAGE (the true surface sits closer on the enemy-facing side), ~2 frames latent. The Game player's shield UI/damage logic reads it
* `ForceEmitter::setShellAlpha(alpha)` (`outputParams.y`, default 1): shell opacity; 0 SKIPS the ray-marched shell draw entirely while the field stays live (deforms bubbles, force/pressure/query readbacks). Invisible fields also never TINT other shells: shading weighs team color + contact glow by alpha-scaled fields (`forceAccumulateVisible`), and an equilibrium wall against an invisible side reclassifies as the visible team's SKIN (shaded + owned by that team — the invisible proxy never rasterizes, so pane-classified walls would silently drop). `ForceFieldPipeline::upload` partitions the compaction drawable-first and sets the draw instanceCount to the drawable count only (compute dispatches keep the full count). This is how a map-scale invisible emitter (the Game world field) avoids a full-screen march — combined with the big-emitter list it needs NO other special support

## Spatial
* High-performance spatial index for culling and position lookup, independent of the entity hierarchy. Implicit 64-ary hierarchy over per-level hashed grids — 11 levels, cell size ×4 per level (finest = compile-time `SPATIAL_FINEST_CELL_SIZE`, default 2 m → ±2097 km), BMI2 Morton keys (`Spatial:Morton`), each `CellRecord` holds a 64-bit child-occupancy mask so queries descend with bit scans. API takes dvec3 (quantized to an int64 lattice); per-entry data is SoA with cell-relative float positions; query math is reference-relative float — exact at planet scale
* `Globals::spatialIndex`: `initialize()` before world spawns; `registerEntry(pos, radius, userData, layerMask)` → `SpatialHandle`/`SpatialEntry` RAII; `updateEntry` per frame (same-cell rewrite ~4 stores; cell changes staged into PerWorker lists — callable from any job, one visitor per entry; register/unregister/commit/setLayerMask are main-thread); `commitFrame()` once per frame drains + sweeps. Queries read-only between commits: `querySphere/queryAABB/queryFrustum/queryRay/queryNearest`. Two visibility stamp sets (`markVisibleSet(Main, frustum)` + `markVisibleSphere(Near, ball)`; `getPassMask`/`isVisible`); the App drives all of it through ONE call, `SpatialIndex::update(camera, frustum, viewProjRelCamera)` (main loop after beginFrame: commit + cull-dist + mode/freeze gate + margin-inflated Main stamp with occlusion + Near ball with requery hysteresis)
* Entity integration: every RenderComponent auto-registers on spawn (bounds from `RenderNode::getWorldBounds`, skinned × "Skinned radius scale", layer `SpatialLayer_Render`); update pushes per-pass masks — Main-visible entities push `PASS_ALL`, Near-only push `PASS_SHADOW|PASS_GI` so shadows/GI keep off-screen entities. `Spatial/Culling/Mode`: Off / Stats only / Cull (default) / Main only (debug — visibly kills off-screen shadows/GI); `Freeze` stops re-stamping to inspect the culled set
* CPU software occlusion (`Spatial:Occlusion`, `Globals::occlusionBuffer`, Spatial/Occlusion tweaks, default off): the largest triangles of static mesh colliders (from CollisionCache occluder sets, registered by PhysicsComponent, RAII `SpatialOccluder`) rasterize camera-relative into a 256x144 CPU depth buffer + 8x8 max-depth blocks; plugged into the Main stamp as `IOcclusionTester` — occluded cells drop from the MAIN pass only. Conservative toward visible
* Static tier: entries unchanged for N frames (Spatial/Static tweaks) promote into per-level Morton-sorted SoA ranges (`StaticStore`), budgeted one level per commit; any change demotes. Sphere/AABB/frustum testers all test static ranges 8-wide (AVX2 `test8`)

## Profiling
* CPU + GPU scope profiler, part of Core: `Core.Profiler` (`Globals::profiler`), re-exported from `Core.ixx` (its interface must not import Core back — textual std includes in the GMF)
* `ProfileScope scope("Name", EProfileCategory::Physics);` — RAII, name MUST be a string literal. ~15ns hot path: two rdtsc + one 32-byte store into the calling thread's lock-free single-writer ring (`ProfileTrack`, 32K records/1MiB, overwrite-on-wrap)
* Thread registration is EXPLICIT-ONLY: every profiling thread calls `registerThread(name, sortKey)` at startup (main registers as "Main" in the profiler's static-init ctor; workers in `workerMain` with `SORT_KEY_WORKER + index`). A ProfileScope on an unregistered thread debug-asserts and no-ops. Registered: Main, JobWorkerNN, GPU, TexStream/MeshStreamer, V3 Loader, JobTimer. Deliberately unregistered: transient startup pools + stress-test threads (tracks are permanent, 1 MiB each) and miniaudio's thread
* Scopes MAY span a JobSystem `wait()`: the open-scope stack MIGRATES with the parking fiber (`suspendScopes` at both park sites closes on-thread segments; `resumeScopes` replays on the resuming thread). Timing = sum of on-thread segments (parked time not counted); memory attribution follows the fiber. `ProfileScope` caches NO track pointer. Max migrating depth 32
* Records push at scope END (rings ordered by end time). `Profiler::endFrame()` (main loop, after present) pushes a frame mark (512-frame ring) and re-anchors rdtsc↔QPC calibration. The profiler self-initializes at static init; `endStaticInit()` FIRST THING in main() closes the synthetic "Static init" scope (static-init allocations attribute there). Recording is always on; the panel's PAUSE freezes the data, not the bookkeeping (`setPaused`: ring pushes drop, open/close keeps running so migration + Memory attribution stay live; resume lays a GAP pseudo-frame, `isFrameGap`)
* GPU pass timings: `GpuProfiler` (RendererVK Objects/, member of Renderer) writes timestamp pairs in the primary CB around each pass (outside render passes only — multiview would replicate); one query pool per frame slot, results read in beginFrame after the fence, pushed into a named "GPU" track. GPU↔CPU alignment via VK_KHR_calibrated_timestamps, fallback submit-tick anchoring
* UI "Profiler" panel (`UI:ProfilerPanel`): frame bar graph (click = pause + inspect; Space = pause), per-track flame graphs (zoom/pan/fit), sortable stats table. Live view shows frameCount-3 so CPU and GPU data are complete

## Memory
* Allocation tracking + treemap, part of Core: `Core.MemoryTracker` (NOT re-exported from Core.ixx; its only consumer is the UI Memory panel). `Globals::memoryTracker` attributes every allocation to the PROFILE-SCOPE PATH open on the allocating thread: allocator hooks (`g_memoryAllocHook`/`g_memoryFreeHook` in Core.Allocator; alloc fires after allocation, free before release) walk/build a `MemScopeNode` tree (4096-node pool); live pointers in a 64-shard open-addressing map (preallocated)

## Threading
* Fiber-based work-stealing job scheduler. Jobs run ON Win32 fibers, so `wait()` inside a job PARKS the fiber and frees the worker; the fiber may resume on a different thread — hence `/GT` everywhere: never cache `thread_local` addresses (or `PerWorker::local()`) across a wait
* `Globals::jobSystem`: `initialize()` MUST run on the main thread (registers it as helper: main-thread `wait()` runs jobs); shutdown is ~JobSystem at init_seg XCU5 (idempotent `shutdown()`; atexit runs on the main thread — see Style for the teardown scheme). `submit(callable, priority, &counter, name)` / `submitDelayed` (timer thread) / `wait(counter)` / `parallelFor(begin, end, grain, fn)` (shared cursor, caller participates, nestable). Callables store INLINE (`Job::StorageSize` 64, `sizeof(Job)` 128, both static_asserted — capture a pointer to bigger state). Counters/data captured by reference must outlive the wait
* Scheduling: per-context Chase-Lev steal deque (`Threading:StealDeque`) + 3 shared Vyukov MPMC priority rings (`Threading:MPMCQueue`) + resume queue + free-fiber/job pools — all preallocated, hot paths lock-free, zero runtime allocation. A worker's own continuations go to its LOCAL deque regardless of priority (fork/join locality). Idle workers spin then sleep on an eventcount. On pool/queue exhaustion submits execute INLINE with a debug assert — raise `JobSystemDesc` capacities
* `Threading:JobSync`: `JobMutex` (fiber-parking mutex — use for long exclusive sections like V3 inference so waits hold a fiber, not a worker), `JobEvent` (manual-reset, idempotent signal), `PerWorker<T>` (cacheline-aligned per-context slots, `.local()`/`.forEach()` — the substrate for per-worker queues/dirty lists)
* Job cost heuristic: graph nodes are wall-time EMA'd (timing is opt-out via `EJobFlag_Untimed`; parked waits count); each `run()` recomputes critical-path ranks and promotes top-rank Normal jobs to High. `parallelFor(begin, end, JobCost&, fn)` auto-grains toward `parallelForTargetChunkNs` (25µs) with per-call feedback. Ad-hoc submits are deliberately untimed
* `JobGraph` + `JobResource` (`Threading:JobGraph`): declared-access DAG — `addJob(name, fn).reads(a).writes(b).after(id)` derives hazard edges render-graph-style in declaration order; edges always point earlier→later so cycles are impossible. `compile()` once, `run()`/`wait()` per frame, zero allocation, re-runnable. `JobResource` is a process-unique id created next to the data it names
* Stress harness (`Globals::jobSystemStress`, Threading/Stress tweaks): throughput/parallelFor/hazard-checked-graph/fiber benchmarks + "Run self test". The way to re-verify changes here is a temp console torture target
* Invariants (each guards a race that was actually hit): a waiter may FREE the counter the instant it observes zero, so `isDone` is "the FULL value is zero"; fiber-wait registrations ride the high 8 bits (`JobCounter::WaiterInc`) keeping the value nonzero; the zero transition claims the wait list with ONE exchange of a taken-sentinel; the only post-zero touch is an address-only `notify_all`. A parked fiber's wait node lives on its stack (signaler spins on `switchDone`); `runFiber` reads fiber state BEFORE publishing `switchDone`; recycling freelists are LIFO tagged-index stacks, NOT rings (a preempted ring pop fakes full/empty — this exhausted the job pool in practice); inline helping in `wait()` is depth-capped. Don't hold a fiber wait across `shutdown()` (asserted)

## Procedural
* The procedural world layer: diffusion terrain, FFT ocean, scattering, terrain physics, and the camera-centered bakes they share. `Globals::terrain` (TerrainStreamer), `Globals::terrainCollider` (TerrainCollider), `Globals::ocean` (OceanGenerator), `Globals::scatter` (ScatterSystem) — all in init_seg `OC_SEG_PROCEDURAL`, the first globals to destruct (their dtors free renderer residency / collider bodies and may wait on in-flight jobs; order among them is undefined and deliberately independent). main.cpp updates all four per frame in order terrain → collider → ocean → scatter (after entity updates, before present). `ocean.swellTravelAngle()` → `terrain.setFlowWindAngle` is wired once at init
* `ITerrainSampler` (`:TerrainSampler`): THE terrain field interface — pure functions of world (x,z), seeded/thread-safe/world-continuous, held as `shared_ptr<const>` (workers finish against old maps across rebuilds). `samplePoint`/`sampleGrid` fill a `TerrainPoint` (height, water level, temperature + sea-level baseline, humidity, fog, flow angle) in ONE evaluation — wide-area consumers must use `sampleGrid` (hoists per-point overhead; for V3, one lock per tile). `ESampleDetail::Coarse` for km-scale bakes. One `lapseRatePerMetre()` for the whole world
* `TerrainGenV3` (`:GeneratorV3`, `Private/Diffusion/`): ONNX diffusion pipeline (ONNX Runtime + DirectML, 2.28 GB models loaded once per process, reseeded never reloaded; the load is DEFERRED until "Terrain/Enabled" — `rebuildMaps` early-outs disabled without constructing the generator, and constructing it is the only load kick. No unload API: disabling after a load keeps the models resident). 256x256 tiles (7.68 km at native 30 m/px; `metersPerPixel` is a uniform world scale); a point read is a bilinear tile fetch; a cold tile ~1.5 s with inference serialized by a fiber-parking JobMutex; concurrent requesters park on a per-tile JobEvent. Tiles cache to disk under `Assets/Local/Diffusion/<seed>/` (zstd). Sub-30 m relief is slope-masked noise (`:Noise` fbmEroded). `isReady()` gates everything until models load (else a flat world bakes into caches)
* `TerrainStreamer` ("Terrain*" tweaks): render-only chunk streaming — bounded LOD ring around the camera, generated on up to "Gen jobs" self-continuing Low-priority pump jobs (`kickPump(n)` CAS-claim + exit-recheck protocol, nearest-first; `createMeshScene` runs IN the pump, main only initializes the container; warm-tile mesh builds overlap cold V3 waits since those park fibers). Chunks leaving the ring free all GPU residency (`~ObjectContainer`). Owns THE world datum other systems consume, handed out not duplicated: `seaLevel()`, `activeWaterReach()`, `activeFlowField()`, `activeClimateMaps()`, `activeTerrainData()`. Also bakes the shared TERRAIN-DATA MAP (2 near/far cascades, RGBA32F: height, water level, packed fog|flow|temp|humidity → `Renderer::setFogTerrainHeightMap`; consumed by fog terrain-follow, ocean depth/level (GPU via terrain_height.inc.glsl + CPU copy for buoyancy/wind steering), terrain coloring, the terrain sun march) and the splat textures (BC-baked to Assets/Local/TerrainTex at startup)
* `HeightMapBaker` + `applyWaterReach` + `applyFlowField` (`:HeightMapBaker`): the async snapshot bake driver — one Low job in flight (JobCounter-polled), re-bakes on camera drift > range/4 or config change (configs carry `operator==` so tweaks stay live), center snapped to the coarsest texel lattice. WaterReach: chamfer distance-to-ocean sinks the baked water level under ground the ocean can't reach (keeps beaches off inland hollows). FlowField: 8-bit per-texel flow direction — toward land through the surf zone, downhill elsewhere; baked into both maps' flow bits
* `OceanGenerator` ("Ocean*" tweaks): CPU side of the FFT/Tessendorf ocean — camera-following geometry clipmap (fixed cell size per ring, CDLOD morph; a FLAT "Horizon band" ring extends to the far plane so the sea always meets the horizon) split into SECTORS (each an ObjectContainer/RenderNode + SpatialEntry on `SpatialLayer_Terrain`, one shared snapped transform, duplicated border verts): the Spatial Main gate skips off-screen sectors (ocean is PASS_MAIN only) and a "Dry sector cull" skips sectors fully buried AND inside the streamed-mesh radius. The horizon band is exempt from BOTH under-terrain culls (negated cell size flags its vertices — its huge triangles break the vertex cull's footprint assumption). The simulation (spectrum → IFFT → displacement/gradient maps, re-evaluated every frame so every param is live) is `OceanSimulationPipeline` in RendererVK. Bakes NOTHING itself — shoaling/surf/swash/land cull all read the streamer's terrain-data map. `sampleWaterHeight` = CPU buoyancy field from the GPU displacement readback (App wires it into `PhysicsWorld::setWaterSurface`); its `sampleDisplacement` is a full CPU MIRROR of `oceanSampleDisplacement` (ocean_wave.inc.glsl) — the shader is what you see, the mirror is what floats on it: changing either without the other is a silent bug (bodies sink through drawn waves / float on dry sand). Returns -FLT_MAX only past the run-up band; inside it the drawdown floor sinks the surface under the sand (beaches bodies). WIND: the dominant spectrum term travels AGAINST `windDirection` — swell heading = `swellTravelAngle()` = wind + π; `steeredWindAngle` slews the SIM wind toward the baked shore flow so waves roll inland (per-pixel domain rotation is disabled in ocean_wave.inc.glsl — creases; see the comment before reviving). "Ocean/RT" tweaks budget per-pixel scene rays
* `TerrainCollider` ("Terrain/Collision" tweaks): camera-centered ring of small static triangle-mesh collider tiles (default 32 m tiles within 96 m, 1 m spacing = the render LOD0 lattice, so bodies rest on the drawn surface). Never touches the render chunks: each tile is `sampleGrid`'d + BVH-built (`createCollisionMesh`, standalone/thread-safe) on ONE in-flight Low job, nearest-first; main thread only creates/destroys the static bodies (layer "Terrain"). Tiles clear on sampler identity change; half-tile eviction hysteresis. Verify with Draw colliders
* `ScatterSystem` ("Scatter" tweaks): trees/rocks/grass — config is two function-local tables in Scattering.cpp (`scatterAssets()`: .oc models with footprint/scale/slope settings; `scatterRules()`: climate ATTRACTORS in real units (°C, mm/yr) with Gaussian falloff — no biome enum). Cell placements computed deterministically on pump jobs (same claim protocol, "Scatter/Gen jobs") from the SAME sampler the terrain renders (footprint dart-throw, cluster noise, slope/altitude bands); per-rule `viewDistance` spawns/despawns instance groups without regenerating cells; everything regenerates on sampler identity change

## Network
* Winsock UDP/TCP + reliable-UDP game protocol (Core-only; Ws2_32 + Bcrypt PRIVATE). Partitions `:Address`, `:Serialization`, `:Socket`, `:Crypto` (internal), `:Reliable`, re-exported from `Public/Network.ixx`. IPv4 only; raw little-endian wire format, no versioning — both ends must match (`protocolId`). `NetHost` is strictly single-threaded, main-thread-only
* `:Serialization`: `NetWriter`/`NetReader` over caller-provided spans — trivially-copyable `write<T>`/`read<T>`, varint (LEB128 + zigzag), strings, unorm/snorm/`writeQuantized`; overflow-safe (`overflowed()`), reads are zero-copy views
* `:Socket`: non-blocking RAII — `UdpSocket` (big SO_RCVBUF, SIO_UDP_CONNRESET disabled), `TcpSocket`/`TcpListener`, `TcpMessageStream` (length-framed), `netResolveHost`. Winsock initialized lazily
* `:Reliable`: `NetHost` — symmetric client/server/p2p over one UdpSocket (simultaneous handshake tie-broken on connect salts). Poll model: `send(peer, bytes, ENetDelivery, channel)`, per-frame `update(dt)` (batches into ≤maxPacketSize packets), drain `takeEvents()`. Deliveries: Unreliable, UnreliableSequenced, Reliable (ordered, ack bitfield piggybacked on every packet, RTT retransmit, transparent fragmentation) on 8 channels (channel rides the kind byte, zero wire cost — bulk transfers don't head-of-line-block). 4-way anti-spoof challenge handshake (responder stateless until the challenge round-trips); `NetHostConfig::encrypt` adds ephemeral ECDH P-256 + AES-128-GCM per payload packet (+16B; Windows CNG, hardware AES) — secure against spoofing/eavesdropping/tampering, not active MITM. Keepalives/timeouts, per-peer RTT/loss stats, live link sim (`simPacketLoss`/`simLatencyMs`/`simJitterMs`)
* ABUSE LIMITS (`NetHostConfig`, enforced before any parsing/allocation): per-source-address token bucket in a FIXED 512-slot hash table (a per-address map would itself be the memory attack; a foreign slot is only stolen once its owner has refilled — else a flooder evicts active peers; an UNUSED bucket must be claimable on the first packet); `maxPacketsPerUpdate` bounds one update globally; `maxPeersPerIp`; `maxQueuedReliablePerChannel` disconnects never-acking peers (`ENetDisconnectReason::Overflow`, latched and acted on in update() — never free a peer inside send()). `NetHostStats::packetsDroppedPerSec` surfaces rate limiting (server title bar)

## NetFuzz
* `Code/NetFuzz` (console exe, Core + Network; VS target `run-netfuzz`): protocol fuzzer, the regression gate for wire-format changes. `NetFuzz reader|host|game|all [iterations] [seed]` — deterministic seed printed
* `reader`: any view NetReader returns must lie inside the input buffer. `host`: drives a real in-process NetHost (cold-start, pre-auth garbage, authenticated payloads via real handshake; also smoke-tests the encrypted path). `game <ip[:port]>`: the only mode reaching NetworkManager's handlers — hostile client vs a live `App --server --headless` run with `--no-encrypt` (it speaks the handshake by hand and mirrors `GameProtocolId`)

* Gizmo split: `UI.Gizmo` declares `EGizmoMode` + `IGizmo`; Input's GizmoController implements it; main owns the object and does `ui.setGizmo(&gizmo)`. `UI::update` drives it after panels settle viewport rect + selection; main calls `ui.drawGizmoEntity(renderer, dt)` at the entity-update point

## Input
* SDL3 event pump; listener objects with std::function callbacks. `addKeyboardListener()`/`addMouseListener()`/`addSystemEventListener()` return move-only RAII handles (`InputListenerHandle<T>`, InputDef.ixx) that unregister in their destructor — assign callback slots through `->`; no manual remove API
* `GizmoController` (in Input because it needs mouse listeners + viewport focus; DRIVEN by the UI via `IGizmo`): spawns `Entities/Gizmo.pre`, follows the Scene selection, constant apparent screen size, T/R/G switches Translate/Rotate/Scale, drag writes back to the entity (a kinematic/static physics body does NOT follow — see PhysicsComponent)
* `VrInput` (`Globals::vrInput`): OpenXR controller input via `Core.VrSession`'s `IVrSession`
* Camera controllers: `FreeFlyCameraController` (WASD+mouse) and `VRFreeFlyCameraController`; App picks by `renderer.isVrEnabled()`

# Asset files
All text formats parsed via `AssetParser`, registered by `AssetRegistry`:
* `.oc` (ObjectContainer): `ObjectContainer <name>` + `Path`, optional `Loader Procedural`, `MergeNodes`, `PreTransformVertices`, `DecimationFactor` (<1 meshopt-simplifies at cook; cache-only, so skinned/procedural containers never decimate), `MaterialOverrides` (per-material `PipelineIdx <pipelineName>`, `ExcludeFromRayTracing`, `UseSceneTextures`, `DiffuseTexIdx`/`NormalTexIdx`/`MetalRoughnessTexIdx`). Skinned containers MUST keep `PreTransformVertices false`
* `.pre` (Prefab): `Prefab <name>` root with `Component Render/Animator/Script/Physics/Audio/Particle/Force/Light/Network/Scene` children; `Component Scene` nests child `Prefab` references. Render requires `ObjectContainer <name>` + `Node <path>`, `Type StaticMesh|SkinnedMesh` (skinned adds a nested `Rig <name>`), plus `Position/Rotation/Scale`; entity-level `Enabled false` authors the disabled state. Spawn by prefab name (`world.spawn`) or path (`world.spawnAssetFile`)
* `.anm`: `Animation <name>` clips — source `ObjectContainer`, `Loop`, `Skip` (channels), `Event <name> <normalizedTime>` notifies (fired into the entity's script/animator `onEvent`)
* `.apl`: `Animator <name>` graph — `Parameter`s (Float/Bool/Trigger), `Clip <name>` + `Anim <clipName>` bindings, `BlendSpace1D` with `Sample`s, `StateMachine` (`Entry <state>`, states with `Play`/`SpeedParam`/`SpeedScale`, `Transition`/`AnyTransition` with `Condition`/`ExitTime`/`Fade`)
* `.scr`: the removed node editor's format (generated C++ + `//@graph` metadata) — legacy reference only: reads as plain text in Content, never cooked, no editor. Author `.dsl` via DslCompiler instead
* `Assets/Local/` is generated output (SPIR-V + shader dumps, compiled script DLLs/PDBs, cooked scenes `Cooked/*.vsc` + converted .dds, `TerrainTex/` splats, `Diffusion/` tile cache) — never hand-edit
